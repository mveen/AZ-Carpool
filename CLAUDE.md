# AZ Carpool: rules for Claude (and people) working in this repo

- **Design:** read `DESIGN.md` first. All look-and-feel lives in `tokens.css` + `components.css`. New UI uses those classes and `var(--...)` tokens only (no hex colours, no px font sizes, no one-off styles). `tests/design-rules.test.js` enforces it. There is no legacy stylesheet any more; do not add inline `style="..."` (a test counts them).
- **Texts:** all on-screen Dutch text is in `texts-nl.js` (`t('key')`). Icons via `phIcon()`.
- **Docs:** `README.md` is the map (files, testing, deploy, test environment, rollback). How a feature works and why goes in its own file in `docs/functies/` (listed in the README table), not in the README (`tests/docs.test.js` keeps the README small).
- **Tests:** `npm test` must be green. A changed module needs a changed test file; after a green run do `npm run lock`.
- **Testtelling lokaal ≠ CI (bekende valkuil, opgelost in de oorzaak):** `tests/deploy-rsync.test.js` en `tests/deploy-test-env.test.js` slaan 9 tests over als `rsync` niet is geïnstalleerd (de cloud-container heeft dat standaard niet). Dan telt `npm test`/`npm run lock` 9 minder dan CI en faalt de regel "test-count.js says X" in CI. Draai in een nieuwe cloud-sessie eerst `apt-get update && apt-get install -y rsync` (controle: `which rsync`), pas daarna `npm test` + `npm run lock`. Dan klopt `test-count.js` meteen, zonder handmatige +9. Is rsync echt niet te installeren: zet `TEST_COUNT` op de lokale telling +9 en zeg dat erbij. Nooit `test-count.js` met de hand 'repareren' zonder de oorzaak te controleren.
- **Deploy:** bump `CACHE_NAME` in `service-worker.js` on every change to app files (CI checks it). New app files go in `ASSETS` there.
- **Database:** shared live Firestore. Changes are additive only (new optional fields). Never rename, delete or migrate existing data without asking.
- **Rollback:** tag `v1-stable` = the app before the v2 redesign. Redesign work happens on `feat/redesign-v2`, one PR per phase; nothing reaches `main` without the owner's approval.
- **Try a branch locally:** `npm run preview` (opens nothing; go to http://localhost:8777/). Uses the TEST database (`az-carpool-test`), never live.
- **Test environment:** `test.azcarpool.nl` has its own Firebase project. Put a branch there with GitHub Actions -> *Deploy test.azcarpool.nl* (by hand). Try risky changes there, not on live. See README (*Test environment*).
- **Pushen en pull requests (altijd via de cloud):** de shell op de computer van de eigenaar (`device_bash`) heeft geen GitHub-inloggegevens, dus daar nooit `git push` of `gh` proberen. Werkwijze: gebruik `add_repo` (access `push`) voor `mveen/AZ-Carpool`, clone in de cloud-sessie (`git clone --depth 1`, ruime timeout), pas de wijziging daar toe (eventueel als patch vanaf de lokale map via `device_stage_files`), draai `npm test` + `npm run lock`, push de branch en open de PR met de REST-API: `gh api repos/mveen/AZ-Carpool/pulls -f base=main -f head=BRANCH -f title=... -f body=...` (`gh pr create` werkt niet: GraphQL is geblokkeerd). Haal eerst `origin/main` op: de versie (`CACHE_NAME`/`APP_VERSION`) kan op main al hoger zijn dan lokaal. De eigenaar hoeft alleen te mergen. Vraag niet om GitHub Desktop, tenzij de cloud-route echt faalt.
- **Planning principle (owner, 2026-10-31):** parents drive out of necessity, not for fun; the daughters want to play football, their parents do not. So any choice about rides (advice, planner, merging cars) is tested against: *parents sacrifice, daughters benefit*. Fewer cars (fewer driving parents) come BEFORE less waiting for the daughters, within seats, the max time spread of a car (Beheer, default 3 h) and the hard rules; longer waiting is acceptable as long as a daughter is on time. Without carpooling the daughters need public transport: far more travel time and money. Order in `buildKeepAdvice`: cars, waiting, drivers who notice, broken rules, girls in another car. Tests: `keep PRINCIPLE` in `tests/weekrooster-impact.test.js`. Do not reverse this without asking the owner.
